# Execution Plan: Episode Medical Record Code

Date: 2026-08-13

## Status

Completed

## Outcome

Every episode has a short, immutable, human-readable medical-record code that can be searched and is protected from duplicates by the database.

## Context

- `src/main/java/com/vietnam/pji/model/medical/PjiEpisode.java`: episode persistence and JSON response authority.
- `src/main/java/com/vietnam/pji/model/medical/Patient.java`: established year-plus-random-code generation pattern.
- `src/main/resources/db/migration/`: Flyway owns schema evolution; Hibernate runs with `ddl-auto: validate`.

## Scope

In scope:

- Additive episode code field generated by the server.
- Deterministic backfill for existing episodes.
- Database not-null and unique guarantees.
- Focused generation and migration validation.

Out of scope:

- User-editable episode codes.
- Renaming episode IDs or changing existing episode API routes.

## Approach

Add an immutable `medical_record_code` column, backfill existing rows from their unique IDs, add a unique constraint/index, and generate compact `BA` + two-digit year + random uppercase hexadecimal codes for new entities before persistence.

## Risks And Recovery

- `PjiEpisode` is a critical shared entity; keep the change additive and run the full backend suite.
- Random generation collisions are prevented by the database unique constraint; the long random suffix makes collision probability negligible.
- Recovery: deploy a forward migration that drops the constraint/column and remove the additive entity property. Applied Flyway migrations are not edited in place.

## Progress

- [x] Locate schema, entity lifecycle, and code-generation precedent.
- [x] Run pre-change impact analysis (CRITICAL due to shared entity imports/relationships).
- [x] Add field, migration, and focused proof.
- [x] Run backend validation and impact detection.

## Decisions

- 2026-08-13: Use an immutable 14-character code (`BA` + `YY` + 10 uppercase hex characters); this follows the patient-code precedent while materially reducing collision probability.
- 2026-08-13: Backfill with `BA` + zero-padded numeric ID so existing rows receive deterministic unique codes without random migration behavior.

## Validation

- Focused proof: 3/3 entity code-generation tests passed.
- Integration or end-to-end proof: full Maven suite passed 34/34; application context validated and Flyway validated all 24 migrations against local PostgreSQL.
- Repository-required checks: GitNexus `detect_changes` reported low diff risk with no affected execution processes; reviewed Git diff.

## Result

Episodes now expose an immutable 14-character `medicalRecordCode`. Migration V24 deterministically backfilled existing rows, added not-null/format/unique guarantees, and the full backend suite passed after applying and validating the schema.
